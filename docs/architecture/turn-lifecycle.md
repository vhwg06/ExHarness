# Turn lifecycle

NOOA-G1 adds an explicit runtime-only generation-turn lifecycle without mixing lifecycle telemetry into canonical `AgentEvent` working history.

## Boundary

```text
AgentEvent
= canonical model working history

TurnEvent
= runtime turn lifecycle journal

TraceSpan
= causal execution tree
```

`BEFORE_TURN` / `AFTER_TURN` are therefore never selected into prompt history merely because a model turn occurred.

## Turn interval

A turn is the whole interval owned by one model generation and the work caused by that generation:

```text
BEFORE_TURN N
      ↓
model generation
      ↓
model output
      ↓
action / JavaScript cell / capability / validation
      ↓
AFTER_TURN N
      ↓
BEFORE_TURN N+1
```

The runtime opens a turn immediately before a `MODEL` trace span. A successful model call does **not** close the turn immediately. The turn remains active while the strategy processes that model output.

The active turn closes in one of three ways:

- the next model generation is about to start → `CONTINUE`, `final=false`;
- the strategy returns a result → `RESULT`, `final=true`;
- model/strategy execution fails → `ERROR`, `final=true`.

This makes the boundary useful for later turn-aware context/history work: by `AFTER_TURN`, action and validation effects from that turn have already happened.

## Runtime ownership

`AgentRuntime` owns one `TurnEventStore` and exposes `turnEvents()` for inspection. The runtime wraps the strategy trace surface rather than teaching Predict, action-protocol CodeAct and JavaScript CodeAct three independent lifecycle implementations.

Any built-in strategy model call already goes through `TraceSpanKind.MODEL`, so the same lifecycle contract applies across strategies without changing their model protocol.

Within one invocation:

- turn numbers are generated by the runtime, not trusted from model/strategy output;
- only one turn may be active at once;
- concurrent model generations fail closed;
- each `AFTER_TURN` references the matching `BEFORE_TURN`;
- lifecycle events share the invocation `callId` and judgment metadata.

Strategy-provided `turn` / `attempt` metadata is retained only as `reportedTurn` observability detail.

## Why this is separate from AgentEvent

G1 follows the same semantic distinction that motivated the existing context/history design:

```text
what happened in the model working journal
!=
when the runtime crosses a lifecycle boundary
```

Putting turn hooks into canonical history would make future context-refresh and memory machinery modify the very history it is trying to project. Keeping them separate avoids that feedback loop.

## G2/G3 seam

G1 intentionally stops at lifecycle. It does not yet rerender context or evolve history.

The next stages can attach behavior at deterministic boundaries:

```text
BEFORE_TURN
  → G2: rebuild fresh prompt projection

AFTER_TURN
  → G3: observe completed turn / prepare bounded history evolution
```

No strategy-specific lifecycle API is required for those stages.

## Verification

The G1 regression gate proves:

- Predict validation retry produces two monotonic `BEFORE/AFTER` pairs;
- the first retry closes `CONTINUE`, terminal success closes `RESULT`;
- CodeAct action work occurs inside the open turn before the next model turn;
- model failure closes exactly once as terminal `ERROR`;
- canonical `AgentEvent` history contains no turn lifecycle events;
- full Node 20/22/24 verification remains green.

## Non-goals

G1 does not implement:

- per-turn context rerendering;
- automatic history summarization;
- semantic memory;
- turn events as correctness/evidence claims;
- concurrent model generations inside one agent invocation.
