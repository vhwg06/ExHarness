## Outcome

A real agent change becomes an exact reviewable SCM candidate with current CI evidence and bounded repair.

## Current gap

## Research questions

1. Compare direct SCM API and MCP adapter for exact SHA/tree handling, idempotency and minimal permissions.
2. Select one primary SCM; evaluate GitLab parity requirements without building a second adapter unnecessarily.
3. Define branch divergence, merge conflict, stale CI and ambiguous PR-creation recovery.

## Discriminating experiment

Create a change in a controlled repository, fail then repair CI, move the branch head, and replay a lost create-response.

Specify input fixture, process/provider identities, reset procedure, resource budget, expected output, negative case and pass/fail decision before running. Research may use bounded probes; live credentials or deployment access missing from the environment are explicit prerequisites, never synthetic evidence.

## Required product evidence

- The candidate records base SHA, exact resulting commit/tree, changed files and CI run identities from the real provider.
- A deliberate failing check returns bounded repair; stale checks and unrelated branch updates cannot satisfy candidate acceptance.
- Retry after lost provider acknowledgement discovers the existing change or blocks on ambiguity; it does not create duplicate review requests or bypass merge policy.
