# BB-065 — Neutral benchmark substrate and benchmark package foundation

Status: RESEARCH — PACKAGE ARCHITECTURE CONVERGED CANDIDATE — 2026-09-27.

Canonical benchmark program: `docs/blackboard/process/harness-benchmark-program-research.md`.

## Research reset

BB-065 is reset from the retired DIRECT-vs-ExHarness Core value study.

The old implementation under `scripts/delivery/baseline/**` is legacy from the wrong benchmark premise. It is evidence/history, not the implementation foundation for the new BB-065.

BB-065 now answers only:

> Can ExHarness provide a neutral, reusable benchmark package plus a calibrated substrate whose experiment registration, reset, evidence, accounting and independent-verifier semantics are trustworthy enough for downstream harness and delivery-value studies?

BB-065 does **not** compare ExHarness against another harness and does not make a product-value claim.

Historical runs, provider charges, UNKNOWN usage, candidate artifacts and Jev receipts remain auditable under Git history and their original objective. They are never reinterpreted as evidence for this objective.

## Proposed replacement objective

Outcome:

> A benchmark-only package and pinned neutral substrate reproducibly register benchmark units, isolate attempts, invoke independent verification, preserve complete evidence/accounting and recompute normalized outcomes, producing reusable benchmark contracts for downstream ExHarness experiments without depending on product runtime semantics.

Success criteria:

1. `@exharness/benchmark` owns substrate-independent benchmark contracts for experiment/unit registration, append-only attempts, orthogonal outcomes, evidence identity, nullable accounting and deterministic audit; it has no dependency on ExHarness product runtime packages.
2. A pinned Harbor-based calibration substrate proves clean reset, independent verifier behavior, artifact/evidence collection and audit reopening on deterministic local fixtures plus a bounded external sanity set.
3. Every started attempt is represented with candidate/artifact identity, raw evidence refs, timing and nullable token/cost fields; quality is independent from termination/provider/infrastructure state.
4. The legacy `scripts/delivery/baseline/**` value-study implementation is retired from current execution paths, and no downstream benchmark imports its obsolete Direct/Core/Jev-value semantics.
5. BB-077/081/074 can consume the package through public benchmark contracts and their own adapters without changing the BB-065 core package.

### Package role

`packages/benchmark` is the reusable benchmark kernel.

Initial package identity:

```text
name: @exharness/benchmark
private: true
type: module
runtime: Node >= 20
```

It starts private because BB-065 needs an internal stable boundary, not an externally supported distribution promise. Publishing it later is a separate product decision.

The package MUST NOT import:

```text
packages/core-harness/**
packages/agentic-system/**
scripts/delivery/baseline/**
Blackboard controller implementation
Harbor-specific implementation
provider SDKs
```

The package MAY use Node built-ins and its own pure schemas/contracts.

### Benchmark assets role

`benchmarks/**` owns experiment-specific material:

- substrate adapters;
- pinned external substrate metadata;
- deterministic fixtures;
- workload/cohort manifests;
- run profiles;
- experiment-specific adapters;
- evidence output layout;
- benchmark CLI entrypoints.

This means Harbor is an adapter of the benchmark package, not a dependency embedded into the package contract.

### Dependency direction

Allowed:

```text
benchmarks/substrate/harbor
        ↓
@exharness/benchmark

future BB-077 adapter
        ↓
@exharness/benchmark

future BB-074 adapter
        ↓
@exharness/benchmark
```

Forbidden:

```text
@exharness/benchmark
        ↓
core-harness / agentic-system / Harbor / provider SDK
```

This keeps benchmark truth independent from the system being measured.

## Public benchmark contracts

BB-065 research pins these package-level concepts.

### EXPERIMENT_REGISTRATION_V1

Binds:

```text
experimentId
protocol id/version/hash
evaluated source identity
task/workload manifest identity
environment identity
producer/harness profile identity
resource budget identity
artifact extraction policy
independent evaluator identity
reset policy
registered unit ids
createdAt
```

Registration is immutable after execution begins.

### BENCHMARK_UNIT_V1

A unit is the preregistered comparison atom:

```text
unitId
experimentId
task id + immutable digest
environment identity
prompt/instruction digest
producer profile
repeat index
arm
budget/profile hash
```

Any fixed-factor drift invalidates the unit. It is never silently rewritten.

### BENCHMARK_ATTEMPT_RECORD_V1

Required shape:

```text
schemaVersion
experimentId
cohortId?
unitId
attemptId
retryOfAttemptId?
protocolHash

task:
  id
  bundleDigest
  environmentIdentity
  instructionDigest

runtime:
  substrate
  substrateVersion
  substrateCommit?
  sourceSha
  profileHash

producer:
  kind
  identity
  model?
  provider?

budget:
  wallMs?
  inputTokens?
  outputTokens?
  costUsd?
  toolCalls?

candidate:
  artifactRef?
  artifactDigest?
  extractionStatus

evidence:
  substrateTrialRef
  resultRef
  trajectoryRef?
  verifierRefs[]
  artifactManifestRef?

usage:
  inputTokens?
  outputTokens?
  cachedTokens?
  cacheWriteTokens?
  providerCostUsd?
  normalizedCostUsd?
  status = KNOWN | PARTIAL | UNKNOWN

timing:
  startedAt
  endedAt
  elapsedMs
  providerWaitMs?
  capabilityWaitMs?

quality:
  verdict = ACCEPTED | REJECTED | NOT_EVALUATED
  evaluatorIdentity
  evidenceRef?

termination:
  COMPLETED | BUDGET_EXHAUSTED | AGENT_TIMEOUT | AGENT_ERROR | CANCELLED

providerStatus:
  NONE | RATE_LIMITED | PROVIDER_TIMEOUT | PROVIDER_5XX |
  ROUTE_MISMATCH | USAGE_UNKNOWN

infrastructureStatus:
  NONE | ENV_BUILD | ENV_RUNTIME | ADAPTER_SETUP |
  HARNESS_PROTOCOL | ARTIFACT_EXTRACTION | VERIFIER_ERROR

failureFingerprint?
```

Nullable usage/cost fields remain null when unknown. UNKNOWN is never converted to zero.

### ATTEMPT_LEDGER_V1

Rules:

- unit registration exists before the first attempt;
- attempt start is append-only;
- retry creates a new attempt;
- prior failed/partial attempts remain;
- no successful retry overwrites the original;
- reducers consume all registered attempts according to protocol policy.

### EVIDENCE_MANIFEST_V1

Every attempt evidence manifest binds immutable path/digest identities for:

- raw substrate result;
- candidate artifact;
- verifier output;
- trajectory/tool trace when available;
- usage/provider observation;
- normalization result.

The package never trusts an in-memory summary as sufficient evidence.

### BENCHMARK_AUDIT_V1

Audit must reopen materialized evidence and deterministically recompute:

- evidence digests;
- candidate identity;
- evaluator identity;
- outcome dimensions;
- nullable accounting;
- normalized record digest.

Stored and recomputed records must match.

## Port model

`packages/benchmark/src/ports.js` should define contracts rather than implementations.

Conceptual ports:

```text
SubstratePort
  prepare(unit)
  execute(unit, producer)
  collect(trial)

ProducerPort
  identity()
  execute(taskContext)

EvaluatorPort
  identity()
  evaluate(candidate, evidence)

ArtifactPort
  collect(trial)
  digest(artifact)

UsagePort
  observe(trial)

EvidenceStorePort
  append(record)
  read(ref)
  list(unit)
```

Ports are capability contracts; BB-065 does not impose ExHarness orchestration semantics on implementations.

## Calibration workload

### Local deterministic fixtures

Create four benchmark-owned tasks:

```text
SUBSTRATE-PASS-01
  oracle writes exact expected artifact
  nop verifier fails
  proves reset + independent verifier + artifact collection

SUBSTRATE-ARTIFACT-01
  oracle creates nested artifact + manifest evidence
  nop fails
  proves collection identity and audit reopening

SUBSTRATE-REJECT-01
  producer fixture reports success but artifact is wrong
  independent verifier rejects
  proves producer status != quality

SUBSTRATE-FAILURE-01
  normalization fixtures exercise timeout/provider/unknown usage/
  artifact extraction/verifier error states without a model call
  proves outcome dimensions are orthogonal
```

All local calibration is deterministic and credential-free.

### External sanity

Before BB-065 closes, select two Terminal-Bench 2.1 tasks deterministically:

1. enumerate bundles from the pinned source;
2. exclude task digests already reserved by canonical downstream benchmark plans at Worker start;
3. sort by immutable bundle digest;
4. select the first two tasks whose Harbor oracle passes 5/5 and nop fails 1/1;
5. seal ids/digests before any downstream live model result is read.

No paid coding-model call is required for BB-065.

If fewer than two tasks satisfy the control, BB-065 is INCONCLUSIVE and cannot be DONE.

## Fresh reset contract

Every attempt uses:

- new substrate trial identity;
- clean task environment;
- no reused working directory;
- no reused candidate/artifact directory;
- new benchmark attempt id;
- immutable profile hash;
- separate evidence directory.

Audit rejects:

- pre-existing candidate files;
- changed task bundle digest;
- changed environment identity;
- reused attempt output path;
- missing verifier evidence;
- missing artifact manifest.

## Outcome truth table

| Producer/transport observation | Independent evaluator | Quality | Other state |
| --- | --- | --- | --- |
| producer exits success | verifier pass | ACCEPTED | COMPLETED |
| producer exits success | verifier fail | REJECTED | COMPLETED |
| budget stop after valid artifact | verifier pass | ACCEPTED | BUDGET_EXHAUSTED |
| provider timeout, no candidate | not run | NOT_EVALUATED | PROVIDER_TIMEOUT |
| usage absent | any | unchanged | usage.status=UNKNOWN |
| artifact collection fails | not validly evaluable | NOT_EVALUATED | ARTIFACT_EXTRACTION |
| verifier crashes | no verdict | NOT_EVALUATED | VERIFIER_ERROR |

## Acceptance criteria

### AC-1 — independent package boundary

`@exharness/benchmark` has a documented public contract and no dependency on product runtime, Harbor implementation or provider SDKs.

### AC-2 — pinned neutral substrate

Harbor release/source plus selected calibration task/environment identities are exact and audit-visible.

### AC-3 — reset and verifier controls

Local controls and two external sanity tasks prove fresh reset, repeated oracle success and nop failure without using model outcome evidence to choose tasks.

### AC-4 — complete orthogonal accounting

Every registered attempt is represented; quality is independent of termination/provider/infra; unknown usage remains null.

### AC-5 — evidence reopening

A fresh audit process reproduces candidate/evaluator/outcome identity from materialized evidence and rejects altered/missing evidence.

### AC-6 — legacy isolation

No current benchmark execution imports retired Direct/Core/Jev-value study code or semantics.

### AC-7 — downstream reuse

BB-077 can depend on the benchmark package contract while owning its own DIRECT_CODEACT/CORE_SYNC adapters and economics protocol.

### AC-8 — product boundary

No ExHarness product runtime source is changed by BB-065 and no Core/product value conclusion is produced.
