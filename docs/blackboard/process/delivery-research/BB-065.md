## Selected design

- Reuse pinned mini-SWE-agent in both arms. DIRECT uses the common executor; EXHARNESS wraps it with existing Core observe/act/verification/evaluation/promotion APIs and persisted state. Packages are read-only. Both arms have the same prompt, provider, tools, repair feedback and shared attempt budget.
- Freeze six matched pairs: two runs each of NORM-01, STATUS-01 and ORDER-01, alternating arm order, with independent resets. Repeats are not six independent task families.
- Enforce one concurrent provider request, bounded pacing, request reservations, durable waits, append-only unknown-usage reconciliation, original deadlines and incremental export. Unknown usage cannot become zero or disappear on restart.
- Qualify existing NVIDIA before measured registration. Try thinking-disabled required tools, then thinking-disabled named bash only after resolved failure. First profile passing two structured probes wins; four total wire attempts, 512 output tokens, 300s request/310s supervisor, 30-minute qualification deadline, USD 0.10, concurrency one and 10s pacing. UNKNOWN fences dispatch; output-directory changes cannot reset campaign budgets. Preserve failed probe facts. No purchase, key rotation or mid-cohort switch.
- Code computes checks, counts, ratios, timing and costs. The report contains a reference to Jev evaluation; it cannot author a semantic value verdict.
- CORE_VALUE_V2 adds 24 controlled trials (four faults x three families x two arms) separately from twelve live executions. Exercise actual controller seams for stale candidate verification, producer success against rejected/inconclusive verification, interruption after durable result and restart after finalization. DIRECT retains its safeguards; shared protection is not attributable Core value. Deterministic controls never count as live agent outcomes or establish field incident frequency.
- Jev alone judges evidence, comparability, quality, efficiency, candidate control and recovery, then weighs attributable benefit against measured overhead in the final Choice. The existing efficiency thresholds describe that dimension only. Positive or negative findings are valid; missing evidence is INCONCLUSIVE. No operator/agent override, confidence gate, weighted code verdict or semantic reroll.
- Task budget exhaustion with settled usage and independent candidate verification is a measurable task outcome; continue remaining executions. Provider ambiguity stays incomplete. Repair feedback must be symmetric; durable state/candidate hashes and cohort-scoped session IDs must be verified.
- The trusted evaluator signs validated real responses with an Ed25519 key whose public identity is registered before outcomes. Agent workspaces cannot access evaluator credentials or signing keys. Offline audit checks signatures and exact evidence bindings.
- A positive result is not required for DONE: a supported negative result can satisfy the benchmark objective. Resource exhaustion and INCONCLUSIVE are finite, explicit outcomes, but do not waive the live/value acceptance claims.

The canonical plan resolves fixture checks, resource state transitions, Core port mappings, per-execution metric schema, value rubric, typed questions, provenance, budgets, worker slices, source scope and verification commands. It supersedes the former direct-only implementation plan.
