# BB-065 — Neutral benchmark substrate calibration

Status: RESEARCH RESET — 2026-09-27.

BB-065 is no longer a DIRECT-vs-ExHarness value study. Its job is to make the benchmark substrate trustworthy before any harness or product-value claim is attempted. Historical runs, provider charges, UNKNOWN usage, candidate artifacts and Jev receipts remain immutable evidence under their original bindings; they are not retrofitted into the new protocol.

Canonical cross-topic contract: `docs/blackboard/process/harness-benchmark-program-research.md`.

## Research question

What is the smallest reproducible execution/evaluation substrate that can compare heterogeneous harnesses without confounding model, task, workspace, resource budget or evaluator behavior?

The preferred candidate to investigate is Harbor. Adoption is not pre-decided. If Harbor cannot preserve the required ExHarness native behavior, evidence identities or delivery lifecycle hooks, record the exact incompatibility and choose the smallest alternative rather than extending the old custom runner by default.

## Required controls

Before any harness comparison, research must define and prove:

- pinned task input and starting workspace;
- isolated/fresh environment reset;
- oracle/pass control and no-op/fail control where the workload format supports them;
- independent verifier/validator;
- exact final artifact/candidate extraction;
- trace capture;
- token, tool-call, cost and elapsed-time accounting;
- explicit termination and provider/infra status;
- quality verdict independent from termination/provider status;
- repeat/calibration policy sufficient to expose flaky tasks or environments.

A provider timeout, 429, UNKNOWN usage, budget exhaustion or harness stop is an execution observation. It is not automatically a quality rejection. Conversely, a producer-reported success is not acceptance.

## Neutral harness adapter contract

Research must freeze these fields across harness arms:

```text
model snapshot
task/prompt input
starting workspace
tool/capability envelope
token/cost/time ceilings
artifact extraction
evaluator/verifier
reset policy
```

Only the harness is allowed to vary for a harness-isolation experiment. Native execution behavior is retained and observed rather than rewritten into one common control loop.

## Common run record

The output schema must support at least:

```text
run identity
model + provider identity
harness + config identity
task + workspace identity
candidate/artifact identity
validator result
execution trace ref
input/output/cached tokens
cost / unknown-usage state
model turns
tool calls
elapsed time
termination class
provider/infra class
quality verdict
```

This common record is consumed by BB-077, BB-081 and BB-074.

## Preserved lessons from the previous BB-065 work

The previous work remains useful evidence about benchmark plumbing:

- provider pacing/wait must not silently restart a conversation or consume a semantic attempt;
- fractional deadlines and provider waits need explicit accounting;
- detailed observations must reach the independent evaluator, not only hashes/counts;
- simulated fault outcomes and preassigned expectations are not valid robustness evidence;
- audits must reopen materialized evidence rather than trust in-memory summaries;
- code must not override semantic evaluator verdicts;
- response-less timeout/UNKNOWN usage must not become zero usage or safe replay.

These are substrate requirements, not proof that the previous six-pair study is the right harness benchmark.

## Exit to READY

BB-065 can become READY only when:

1. neutral substrate/adapter is selected and pinned;
2. calibration workload and oracle/no-op controls are frozen;
3. reset/artifact/verifier contracts are executable;
4. common run-record schema and accounting are exact;
5. provider/infra/termination vs quality semantics are explicit;
6. repeat/calibration policy and finite budgets are preregistered;
7. old custom DIRECT-vs-Core protocol is either retired or clearly scoped as non-canonical;
8. exact worker source scope and verification commands exist;
9. a fresh Jev readiness judgment binds the new plan.

No ExHarness value conclusion is an exit criterion for BB-065.
