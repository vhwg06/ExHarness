## 3. Selected design (unchanged unless stated)

- Reuse pinned mini-SWE-agent in both arms. DIRECT uses the common executor through the one shared seam; EXHARNESS wraps it with existing Core observe/act/verification/evaluation/promotion APIs and persisted state. Packages are read-only. Both arms have the same prompt, provider, tools, repair feedback and shared attempt budget.
- Freeze six matched pairs: two runs each of NORM-01, STATUS-01 and ORDER-01, alternating arm order, with independent resets. Repeats are not six independent task families.
- Enforce one concurrent provider request, bounded pacing inside the same mini process, cumulative wait caps, single POST→poll deadlines, request reservations, durable waits, append-only unknown-usage reconciliation, original deadlines and incremental export. Unknown usage cannot become zero or disappear on restart. Provider waits are never active execution time.
- Qualify existing NVIDIA before measured registration. Try thinking-disabled required tools, then thinking-disabled named bash only after resolved failure. First profile passing two structured probes wins; four total wire attempts, 512 output tokens, 300s request/310s supervisor, 30-minute qualification deadline, USD 0.10, concurrency one and 10s pacing. UNKNOWN fences dispatch; output-directory changes cannot reset campaign budgets. Preserve failed probe facts. No purchase, key rotation or mid-cohort switch.
- NEW admission gate: after qualification, run the preregistered runtime-readiness canary (section 4) on the frozen profile. No cohort registers without qualification-then-canary pass. Canary fail/UNKNOWN blocks dispatch and creates no new campaign. Qualification A/B order is unchanged and no profile is chosen by fix quality. A canary pass is necessary, never sufficient, for later provider availability.
- Code computes checks, counts, ratios, timing and costs. The report contains a reference to Jev evaluation; it cannot author a semantic value verdict.
- CORE_VALUE_V2 keeps 24 controlled trials (four faults x three families x two arms) separately from twelve live executions, now through the shared DIRECT seam and the real Core adapter with real fault injection and trace-measured counters. DIRECT retains its safeguards; shared protection is attributed COMMON, never Core. Deterministic controls never count as live agent outcomes or establish field incident frequency.
- Jev alone judges evidence, comparability, quality, efficiency, candidate control and recovery, then weighs attributable benefit against measured overhead in the final Choice. The existing efficiency thresholds describe that dimension only. Positive or negative findings are valid; missing evidence is INCONCLUSIVE. No operator/agent override, confidence gate, weighted code verdict, semantic reroll, or validator veto.
- Task budget exhaustion with settled usage and independent candidate verification is a measurable task outcome; continue remaining executions. Provider ambiguity stays incomplete. Repair feedback is symmetric and bounded; durable state/candidate hashes and `manifest.cohortId`-scoped session IDs are verified with no cross-cohort joins.
- The trusted evaluator signs validated real responses with an Ed25519 key whose public identity is registered before outcomes. Agent workspaces cannot access evaluator credentials or signing keys. Offline audit checks signatures and exact evidence bindings. Stage two embeds the verbatim stage-one triple.
- A positive result is not required for DONE: a supported negative result can satisfy the benchmark objective. Resource exhaustion and INCONCLUSIVE are finite, explicit outcomes, but do not waive the live/value acceptance claims. With fixed Lightning, a decisive judgment cannot be guaranteed if the provider keeps withholding usage — retain the specific blocker and recovery evidence instead.

The canonical plan resolves fixture checks, resource state transitions, Core port mappings, per-execution metric schema, value rubric, typed questions, provenance, budgets, worker slices, source scope and verification commands. It supersedes the former direct-only implementation plan.

## 5. Semantic authority and evidence rules

- The three stage-two Choice descriptions in the READY plan (`VALUE_DEMONSTRATED` / `NO_VALUE_DEMONSTRATED` / `INCONCLUSIVE`) are the only value criteria. The full rubric paragraph containing all three conclusions is never a VALUE_DEMONSTRATED criterion.
- The code validator checks typed schema, identity, evidence completeness, signatures, budgets and stage binding only. It never derives or vetoes net value from dimension combinations. `consistencyCheck()` semantic inference is deleted.
- Stage two receives the verbatim stage-one answers plus evidence; the stored choice is Jev verbatim with no confidence gate, voting or reroll.
- Both Jev stages receive full `state.study` observations (failures, denominators, study limits, hash-bound ledger summary). Either stage exceeding 24000 UTF-8 bytes is an explicit materialization error, never silent truncation.
- Factual audit runs before any production Jev call; missing/corrupt evidence means no Jev call.
- Export bundle carries both stage requests/responses/receipts; audit and complete consume the same factual evidence.
- New fixed-run registrations, reports, controlled trials, Jev receipts and value pointers use a new schema/evidenceClass discriminator. Old runs, charges, UNKNOWN and receipts stay under pinned bindings and are never retrofitted. Terminal artifacts are never rewritten.
