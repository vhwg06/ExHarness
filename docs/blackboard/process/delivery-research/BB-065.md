## Proposed replacement objective

## Calibration workload

### Local deterministic fixtures

Create four benchmark-owned local Harbor tasks.

```text
SUBSTRATE-PASS-01
  oracle: writes exact expected artifact
  nop: verifier fails
  proves reset + independent verifier + artifact collection

SUBSTRATE-ARTIFACT-01
  oracle: creates nested artifact + manifest evidence
  nop: fails
  proves collection identity and audit reopening

SUBSTRATE-REJECT-01
  producer fixture reports success but artifact is wrong
  independent verifier rejects
  proves producer status != quality

SUBSTRATE-FAILURE-01
  normalization fixtures exercise timeout/provider/unknown usage/
  artifact extraction/verifier error states without a model call
  proves outcome dimensions are orthogonal
```

All local fixtures are deterministic and credential-free.

### External sanity

Before BB-065 closes, select two Terminal-Bench 2.1 tasks deterministically from the pinned snapshot:

1. enumerate task bundles from the pinned source;
2. exclude tasks already reserved by a canonical downstream benchmark plan at worker start;
3. sort by immutable bundle digest;
4. select the first two tasks whose Harbor oracle passes 5/5 and nop fails 1/1;
5. seal their task ids/digests in the calibration manifest before any downstream live model result is read.

No paid model call is required for BB-065.

If fewer than two tasks satisfy the control, BB-065 is INCONCLUSIVE and cannot be DONE.

## Fresh reset contract

Every calibration attempt uses:

- a new Harbor trial identity;
- a clean task environment;
- no reused working directory;
- no reused candidate/artifact directory;
- a new benchmark attempt id;
- an immutable profile hash;
- a separate evidence directory.

The audit rejects:

- pre-existing candidate files;
- changed task bundle digest;
- changed environment identity;
- reused attempt output path;
- missing verifier evidence;
- missing artifact manifest.

## Ledger and audit semantics

- Registration creates a unit before execution.
- Attempt start is append-only.
- Retry creates a new attempt and points at the prior attempt.
- No attempt is overwritten or deleted because a later retry succeeds.
- Audit reads the materialized Harbor result/verifier/artifact files and recomputes the normalized record.
- Audit fails if the stored normalized digest differs from recomputation.
- In-memory reducer state is never sufficient evidence.

## Outcome truth table

Examples that must be covered by deterministic tests:

| Producer/transport observation | Independent evaluator | Quality | Other state |
| --- | --- | --- | --- |
| producer exits success | verifier pass | ACCEPTED | COMPLETED |
| producer exits success | verifier fail | REJECTED | COMPLETED |
| budget stop after valid artifact | verifier pass | ACCEPTED | BUDGET_EXHAUSTED |
| provider timeout, no candidate | not run | NOT_EVALUATED | PROVIDER_TIMEOUT |
| usage absent | any | unchanged | usage.status=UNKNOWN |
| artifact collection fails | not validly evaluable | NOT_EVALUATED | ARTIFACT_EXTRACTION |
| verifier crashes | no verdict | NOT_EVALUATED | VERIFIER_ERROR |

## Acceptance criteria

### AC-1 — pinned neutral substrate

Harbor release/source and the selected calibration task/environment identities are exact and audit-visible.

### AC-2 — reset/verifier controls

Local controls and two external sanity tasks prove fresh reset, repeated oracle success and nop failure without using model outcome evidence to choose tasks.

### AC-3 — complete orthogonal accounting

Every registered attempt is represented; quality is independent of termination/provider/infra; unknown usage is null, never zero.

### AC-4 — evidence reopening

A fresh audit process reproduces candidate/evaluator/outcome identity from on-disk evidence and rejects altered/missing evidence.

### AC-5 — boundary

No ExHarness product runtime source is modified and no Core/product value conclusion is produced.

## Negative cases

Must fail:

- stale task digest;
- reused environment/output path;
- producer-authored success with failing verifier;
- timeout represented as quality rejection without evaluation;
- UNKNOWN usage represented as zero;
- missing artifact manifest accepted as complete;
- verifier crash represented as REJECTED;
- retry overwriting a failed attempt;
- in-memory result accepted when materialized evidence disagrees;
- downstream held-out task result read during BB-065 calibration.
