## Selection contract

Selection input is the exact BB-074 report plus its unit-level attempt records.

Eligible fingerprints must satisfy all of:

1. observed in valid registered BB-074 evidence;
2. deterministic fingerprint identity and evidence refs exist;
3. attributable to a mutable HOW/configuration seam rather than WHAT/acceptance/provider availability;
4. can be changed without altering task instruction, evaluator, artifact extraction, resource ceilings or product authority;
5. no missing/unknown primary evidence is required to claim the bottleneck.

Selection precedence is deterministic:

1. repeated critical delivery/recovery failure that maps to an eligible HOW seam;
2. repeated accepted-quality loss/failure fingerprint;
3. repeated provider-economics inefficiency with known accounting;
4. repeated excess model-turn/input-context behavior;
If none qualify, emit `NO_ELIGIBLE_CANDIDATE`; this is not a fifth optimization class.

Within one class, choose the fingerprint with the largest count of affected registered units; tie-break by lexicographic fingerprint id.

"Repeated" means observed in at least two distinct registered units. A single critical correctness/safety failure may be selected only if BB-074 itself classifies it as a primary lifecycle gate failure and the exact HOW ownership is unambiguous.

The reducer output is an immutable `HOW_IMPROVEMENT_SELECTION_V1` record.

## Fresh held-out and release-reserve split

BB-075 must prevent overfitting to BB-074.

At worker start, before candidate construction:

1. pin the same Terminal-Bench 2.1 source snapshot used by the benchmark program;
2. exclude every task digest used or reserved by BB-065, BB-077, BB-081 and BB-074;
3. preflight remaining tasks with Harbor oracle 5/5 and nop fail 1/1;
4. sort eligible task bundles by immutable digest;
5. seal first six as `IMPROVEMENT_HOLDOUT`;
6. seal next four as `RELEASE_RESERVE`;

Task substitution is allowed only before any candidate live run and only by continuing the digest-sorted scan. Once a candidate arm has run, the cohort is immutable.

BB-075 may run model arms on `IMPROVEMENT_HOLDOUT`.

BB-075 must never run model arms on `RELEASE_RESERVE`; BB-076 owns first use of those tasks.

## Improvement metrics

The selected fingerprint maps to one preregistered primary metric family:

### FAILURE_RATE

Use when selection is a repeated deterministic failure fingerprint.

Promotion requires:

- target fingerprint occurs in fewer candidate registered attempts than baseline;
- at least two baseline occurrences are eliminated on matched units;
- accepted quality candidate >= baseline;
- no new critical fingerprint;
- recovery/currentness negatives pass.

### PROVIDER_COST

Use only with known provider cost.

Promotion requires:

- median candidate/baseline provider cost <= 0.90;
- accepted quality candidate >= baseline;
- model turns <= 1.00 ratio;
- no new critical fingerprint.

### PROMPT_INPUT

Promotion requires:

- median candidate/baseline prompt-input tokens <= 0.90;
- accepted quality candidate >= baseline;
- provider cost <= 1.10 ratio when known;
- no new critical fingerprint.

### MODEL_TURNS

Promotion requires:

- median candidate/baseline model turns <= 0.90;
- accepted quality candidate >= baseline;
- provider cost <= 1.10 ratio when known;
- no new critical fingerprint.

A fingerprint that does not map safely to one of these metric families is not eligible.

No significance claim is made from this bounded cohort. Report per-task/repeat deltas and consistency.

## Decision reducer

Outputs:

```text
PROMOTE_CANDIDATE
KEEP_BASELINE
INCONCLUSIVE
```

`PROMOTE_CANDIDATE` requires:

- complete 24-unit registered cohort;
- complete known primary metric;
- all hard quality/safety/currentness gates;
- selected metric minimum effect;
- independent evaluator unchanged;
- exact source/profile/cohort bindings.

`KEEP_BASELINE` is returned only after a real candidate completes the held-out protocol and complete evidence shows insufficient effect or a regression.

`INCONCLUSIVE` is returned for `NO_ELIGIBLE_CANDIDATE`, no delivered bounded seam, missing units, unknown primary metric, verifier/profile/task drift or incomplete negative evidence.

Jev validates the semantic/evidence claims. It cannot convert KEEP_BASELINE into PROMOTE_CANDIDATE.
