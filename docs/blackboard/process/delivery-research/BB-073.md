## Research questions

1. Choose single-tenant local/container packaging and minimal operational prerequisites; defer Kubernetes tenancy unless required.
2. Define runtime/model/SCM compatibility policy, credential configuration and clean-room installation path.
3. Compare CLI-first operation with an operator UI; require a demonstrated workflow need before adding UI scope.

## Discriminating experiment

Ask a fresh operator to follow only the install/runbook artifacts, then exercise one supported upgrade and rollback.

Specify input fixture, process/provider identities, reset procedure, resource budget, expected output, negative case and pass/fail decision before running. Research may use bounded probes; live credentials or deployment access missing from the environment are explicit prerequisites, never synthetic evidence.

## Required product evidence

- A fresh environment installs a pinned release and completes the reference delivery with documented configuration.
- Health checks and actionable errors cover missing credentials, unsupported runtime and incompatible persisted state.
- Upgrade and rollback exercises preserve or explicitly gate ongoing attempt compatibility; runbooks document support boundaries.
