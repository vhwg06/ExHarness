# BB-073 — Ship an installable supported delivery profile

Status: RESEARCH CONVERGED; implementation remains unauthorized until canonical readiness publication.

## Selected architecture

The supported v1 distribution is deliberately narrow:

- **single tenant**
- **OCI/container packaged**
- **Node 24 inside the image**
- **GitHub as the supported SCM**
- **CLI-first operator surface**
- no Kubernetes tenancy, HA control plane or operator web UI

`DELIVERY_RELEASE_MANIFEST_V1` binds the exact source/release, OCI digest, Node runtime major, state-schema compatibility version, runtime/profile refs and required config keys. Mutable tags are not release identity.

The CLI exposes exactly: `doctor`, `configure`, `run`, `status`, `cancel`, `backup`, `restore`, `upgrade-check`. It is a thin adapter over delivered BB-070 lifecycle and BB-072 operations APIs and cannot directly rewrite canonical state.

Configuration is schema-validated; committed examples contain no secrets. Clean install must work from the release bundle/runbook alone, without a developer checkout or prior chat/session state.

Upgrade is fail-closed on active/recovery-required work or incompatible state schema. Rollback uses the exact previous image digest and, when required, the pre-upgrade backup.

OpenHands software-agent-sdk **v1.49.6** remains an upstream runtime profile. Langfuse **v4.46.0** remains optional observability and is not required for installation or health.

## Discriminating verification

A clean temp environment receives only the release bundle, config and runbook, starts the profile and completes the reference delivery. The suite then exercises missing credentials, incompatible persisted state, supported upgrade and exact-digest rollback. Passing requires actionable errors and no hidden dependency on the implementation checkout.
