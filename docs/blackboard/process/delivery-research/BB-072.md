# BB-072 — Make delivery runs observable recoverable and cost bounded

Status: RESEARCH CONVERGED; implementation remains unauthorized until canonical readiness publication.

## Selected architecture

BB-072 adds an **operator projection + controls + optional telemetry export** over existing canonical ExHarness state.

- No second canonical run database is introduced.
- `DELIVERY_RUN_PROJECTION_V1` reconstructs exact task/attempt/model/runtime/SCM/currentness/evidence identities from authoritative stores. Missing observations remain `UNKNOWN`.
- Provider accounting is append-only per wire attempt; failed/retried calls remain in totals and missing usage is never zero-filled.
- `DELIVERY_BUDGET_POLICY_V1` enforces cost/token/call/wall ceilings and blocks new dispatch conservatively when accounting is uncertain.
- status/diagnose/cancel/reconcile are CLI-first. Cancellation and effect reconciliation call existing authority boundaries; they do not rewrite attempts directly.
- Backup/restore is a quiescent digest/schema/release-bound snapshot of canonical single-tenant stores. Telemetry is excluded from authority and can be lost without changing acceptance.
- OpenTelemetry JS **v2.11.0** is selected for optional export.
- Langfuse **v4.46.0** is optional inspection only.
- Temporal **v1.32.0** and Restate **v1.7.11** are rejected as canonical durability layers because they would duplicate execution/recovery authority.

Passing requires exact blocker/provenance explanations, truthful UNKNOWN usage, durable reconstruction and proof that telemetry loss cannot alter acceptance/currentness.
