## Discriminating experiment

Executed research evidence:

- `docs/blackboard/evidence/BB-083/gepa-probe-result.json`
- `docs/blackboard/evidence/BB-083/bridge-probe-result.json`

Negative cases the Worker must prove by executed tests:

- A FeedbackResolution ref whose digest mismatches its artifact, or a non-resolution artifact, is rejected by the projection.
- Two episodes backed by the same observation-ref set, or a retried episode, count as one support unit.
- A SUPERSEDED resolution contributes only through its successor and is never double counted.
- An unmapped finding kind is excluded with UNMAPPED_AXIS and never assigned a guessed HOW axis.
- RECURRING support without mechanism evidence, or mechanism evidence that does not cover every supporting episode, never classifies SYSTEMIC.
- NO_CHANGE and REGRESSED episodes and episode contrary refs remain in contrary evidence; adding positive episodes changes only support metadata and projectionId.
- The projection module exposes no write port; attempts to change response, acceptance, promotion or policy head are impossible and tested by module surface inspection.
- A proposal from an INSTANCE pattern, with more than one HOW axis, an unpinned optimizer identity or any accepted/promoted/approved/verdict/policy-head field is rejected.
- A bridge evaluation request without a successful AttemptLedger reservation is never dispatched; over-budget requests return BUDGET_DENIED before dispatch.
- Crash after a benchmark side effect but before acknowledgement reconciles the exact attempt before any retry; a STARTED-without-SETTLED attempt is never blindly redispatched.
- Cancellation after dispatch keeps the reservation consumed and the attempt auditable; unknown usage/cost stays null, never zero.
- Python attempting repository, benchmark-ledger, product-state or policy-head mutation has no capability path through the bridge; malformed, oversized or timed-out messages fail closed.
- Loading an external or foreign-run GEPA pickle checkpoint is rejected; checkpoint state is never ExHarness evidence.
- Any final-holdout case ref, holdout evidence, metric policy threshold or evaluator acceptance data appearing in bridge input invalidates the run.
- Changing partitions, metric policy, minEffect, WHAT/acceptance, evaluator or fixed factors after search start invalidates the handoff.
- Stochastic final comparison with fewer than three paired repeats per case is INCONCLUSIVE; a critical per-case regression blocks promotion even with aggregate gain.
- buildHowEvolutionHandoff never calls a policy publisher; GEPA acceptance or aggregate gain cannot bypass BB-059 independent evaluation.
- Worker start with BB-085, BB-059 or BB-065 not DONE, missing delivery receipt/Living refs, missing package-root export or a required deep import exits PLAN_INPUT_CONTRADICTION.
- Introducing LangMem, DSPy, LangGraph, gepa[full] or writes under packages/benchmark/**, HOW evolution owners, feedback lifecycle owners, scripts/feedback/** or docs/blackboard/** fail repository verification.
