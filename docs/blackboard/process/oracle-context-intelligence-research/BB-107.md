# BB-107 — Reserve planner work from remaining requirement budget

Status: RESEARCH INPUT; no implementation authority.

Checked: 2026-09-30 against `fdb953c1e85ff32b2d43f61d90bbf245e8aa2ff6` (origin/main).

## Outcome

Per-work reservations use remaining requirement budget so a declared file that fits that budget materializes.

## Current gap

- **DELIVERED_TRUTH.** `packages/oracle/src/retrieval-planner.js` `reserve()` sets `bytes=Math.min(8192, remaining.maxMaterializedBytes-reserved.materializedBytes)` and always `reserved.items++` by 1. `execute()` rejects `raw.length>reservedBudget.items` and `bytes>reservedBudget.materializedBytes` as `BUDGET_EXHAUSTED`.
- **Executed probe.** 9000-byte EXACT file, budget 40000: reserved `{items:1, materializedBytes:8192}`, facade `UNSATISFIED` / `BUDGET_EXHAUSTED` / `provider byte reservation exceeded`. `execute()` failure objects are `{evidenceId,providerId,reason,detail}`; extra `code` is dropped. `detail` is `error.message` (ProviderFailure detail).
- **PLANNED_CONTRACT.** None. BB-091/BB-093 keep DETERMINISTIC_V1 routing and contract budget fields; they do not remove this cap.

## Research revision r1

| Gap | Resolution |
|---|---|
| 8192 cap | `reservedBudget.materializedBytes` = remaining bytes after prior work, not `min(8192, remaining)`. |
| 1-item cap | `reservedBudget.items` = remaining `maxItems` for that work (at least 1 when the work is reserved), not always 1. |
| Over-size still fail-closed | Actual materialization over remaining budget stays `BUDGET_EXHAUSTED`; no truncation. |
| Mapping `code` | Keep `{reason,detail}`; do not add a `code` field to execute() failures. Application already prefixes reader `error.code` into the thrown message. |
| Graph-boundary pin | Update the one-path / `truncated:true` assertion that documents the 1-item reservation. |
