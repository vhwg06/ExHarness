# BB-093 — Implement model-aware context budget profiles

Status: RESEARCH RECORD for a READY plan. The canonical contract is `docs/blackboard/artifacts/ready-implement-plan/BB-093.json`; this document is not implementation authority and adds no claims beyond the objective, plan and readiness judgment.

## Outcome

Oracle requirement budgets can be derived from an explicit model-aware context budget profile so resolved context fits the Core rendered-size limit, with token accounting only under a declared tokenizer and without altering source identity.

## Current gap

BB-064 declares ORACLE_CONTEXT_BUDGETING. BB-061 deferred token budgets because tokenization is model-specific; budgets are raw bytes/items/calls/steps while Core independently truncates rendered context at maxSerializedChars, so nothing guarantees resolved context survives rendering.

## Discriminating experiment

No task-local probe was executed. The design rests on the delivered sources and on the planned contracts listed under Handoff. The Worker must establish the negative cases below by execution.

Negative cases the Worker must prove by executed tests:

- A profile with non-positive counters or a derived maxMaterializedBytes <= 0 is rejected.
- A declared blockEnvelopeChars smaller than the measured Core envelope fails the render-fit test.
- Any fixture whose Core-rendered block exceeds renderedCharCeiling at the derived budget fails.
- measureTokens without a declared tokenizer, or with an injected tokenizer reporting a different id/version, returns UNKNOWN and never a byte-derived number.
- deriveNextStepBudget with any exhausted counter is rejected.
- Over-budget evidence must be BUDGET_EXHAUSTED with whole items dropped; any truncated or altered content fails.
- Oracle source importing Core, or edits to Core/contract/facade files, fail architecture and scope verification.

## Required product evidence

- **BU1**: CONTEXT_BUDGET_PROFILE_V1 validates, has deterministic identity, derives requirement and next-step budgets, and reports tokens only under a matching declared tokenizer identity, otherwise UNKNOWN. Evidence: Unit test output for validation, derivation and tokenizer identity cases.
- **BU2**: For every render-fit fixture, resolving at the derived budget and rendering through Core renderAgentContext yields a block no longer than renderedCharCeiling, with blockEnvelopeChars measured from Core. Evidence: Render-fit test output listing fixture lengths and measured envelope.
- **BU3**: Over-budget context is reported BUDGET_EXHAUSTED with whole items dropped and kept content byte-identical; contract, facade and Core are unchanged and the Living Doc documents the profile. Evidence: Identity-preservation test, Oracle regression and repository verify logs, Living Doc diff.
