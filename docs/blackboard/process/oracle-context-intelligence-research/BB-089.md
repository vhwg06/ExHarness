## Discriminating experiment

No task-local probe was executed. The design rests on the delivered sources and on the planned contracts listed under Handoff. The Worker must establish the negative cases below by execution.

Negative cases the Worker must prove by executed tests:

- Calling resolveBackendContext/resolveQaContext without oracleResolution must never construct an Oracle catalog or resolver.
- A missing, zero or negative maxMaterializedBytes is rejected before resolution.
- An Oracle requirement containing a file or artifact not declared by the order, or omitting one, fails the mapping test.
- A pathless QA artifact on the Oracle path fails with a typed error; the same order on the compatibility path still resolves.
- A repository or artifact reader failure on the Oracle path blocks with SOURCE_FAILURE before any Worker call.
- A manifest-protected artifact whose bytes were changed blocks on the Oracle path exactly as on the compatibility path.
- Declared context larger than maxMaterializedBytes yields BUDGET_EXHAUSTED and blocks; it is never truncated and passed to a Worker.
- Oracle and compatibility contexts that differ in path, content, sourceRef, order or QA provenance fail the equivalence test.
- Edits to Oracle package, Worker, schema, application or manifest files fail repository scope verification.
- runBackendObjective or runQaObjective called with oracleResolution must deliver the Oracle-projected context to the Worker; ignoring the option fails the end-to-end adoption case.
- Edits to durable-backend-qa.js or composition.js fail repository scope verification.
