# BB-092 — Implement bounded explicit progressive resolution

Status: RESEARCH RECORD for a READY plan. The canonical contract is `docs/blackboard/artifacts/ready-implement-plan/BB-092.json`; this document is not implementation authority and adds no claims beyond the objective, plan and readiness judgment.

## Outcome

Applications can explicitly request a bounded next ContextResolution step that re-attempts only retriable unresolved evidence, preserves prior items and cumulative budget, and never grows context or turns implicitly.

## Current gap

BB-064 declares ORACLE_PROGRESSIVE_RESOLUTION. The ContextResolution contract already accepts chained steps and rejects steps beyond maxResolutionSteps, but the delivered facade hard-codes step 0 and takes no previous resolution.

## Research questions

Each objective criterion was a research question; the READY plan resolves it with the listed decisions, acceptance criteria and verification runs.

1. Specify resolveNext(requirement, previous) on the facade producing step index+1 bound to previous.resolutionId, re-attempting only evidence with retriable unresolved reasons under the remaining cumulative budget.
   Resolved by D1, D4, D7; criteria PR1; verification `progressive`.
2. Specify no hidden growth: previous items retained byte-identical, new items only for previously unresolved evidence, requirement identity unchanged and consumption monotonic within budget.
   Resolved by D2, D3, D5; criteria PR2; verification `progressive`.
3. Specify termination and currentness: reject when complete, out of steps or nothing retriable; re-fence all evidence and fail progression when a previously resolved source changed.
   Resolved by D2, D3, D6; criteria PR3; verification `progressive`, `oracle-regression`.
4. Ground the design in the executed progression probe and produce an exact file-level plan, negative cases and executable verification for fresh Jev readiness.
   Resolved by D7, D8; criteria PR1, PR2, PR3; verification `progressive`, `oracle-regression`, `repository`.

## Discriminating experiment

Executed research evidence:

- `docs/blackboard/evidence/BB-091/continuation-probe-result.json`

Negative cases the Worker must prove by executed tests:

- resolveNext with a previous result for a different requirementId is rejected.
- resolveNext on a COMPLETE previous throws ALREADY_COMPLETE; with no remaining steps throws STEPS_EXHAUSTED; with only STALE/AMBIGUOUS/UNSUPPORTED/CURRENTNESS_UNVERIFIABLE/MISSING unresolved throws NOTHING_RETRIABLE.
- A step whose prior items differ in order or content from the previous resolution fails the verbatim test.
- A step adding items for evidence that was already resolved fails the no-hidden-growth test.
- Cumulative consumption decreasing or exceeding the requirement budget is impossible and tested.
- A previously resolved source whose snapshot changed before the next step throws STALE_DURING_RESOLUTION.
- createPinnedResolver given a mismatched requirement throws; Core resolves the pinned block exactly once per call.
- Edits to contract, planner, catalog, durability or Core files fail repository scope verification.

## Required product evidence

- **PR1**: resolveNext returns step index+1 bound to the previous resolutionId for the same requirement, and createPinnedResolver lets Core consume a specific step once per call without Core changes. Evidence: Chaining and Core pinned-resolver test output.
- **PR2**: Only BUDGET_EXHAUSTED/SOURCE_FAILURE/DEFERRED evidence is re-attempted under remaining budget; prior items are byte-identical and cumulative consumption is monotonic within the requirement budget. Evidence: Retriable-selection, verbatim-items and budget monotonicity tests.
- **PR3**: Progression refuses ALREADY_COMPLETE, STEPS_EXHAUSTED and NOTHING_RETRIABLE and throws STALE_DURING_RESOLUTION when previously resolved evidence drifted, with Oracle regressions unchanged. Evidence: Refusal and drift tests, Oracle regression and repository verify logs, Living Doc diff.
