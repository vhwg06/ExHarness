# BB-079 — Implement cache-stable async result context

Status: RESEARCH INPUT; no implementation authority.

## Outcome

Model-visible async operation progress and final results are delivered without unnecessary prompt-prefix rewrites or cache invalidation.

## Current gap

Async operations only save model cost if their state can be surfaced without repeatedly rebuilding or mutating old prompt history. ExHarness has bounded context rendering but no committed-prefix/staged-suffix contract for RUNNING-to-terminal tool results.

## Research questions

1. Define the exact Core context event representation for RUNNING and terminal operation results.
2. Probe at least one OpenAI-compatible and one non-identical provider path for progressive tool-result compatibility.
3. Define measurable prefix/cache stability without relying on unavailable provider cache counters.

## Required evidence discipline

Inspect the current Core source first. Compare the smallest existing-Core design with Unreal Agent v0.2.0 and at least one eligible >=1,000-star public implementation where a second implementation reference is useful. External benchmark claims remain attributed evidence until reproduced on the pinned ExHarness protocol.

The discriminating experiment must hold model/version, source/task fixture, tool surface, resource ceiling and acceptance semantics fixed. Record failures/retries and unknown usage. Include a negative recovery/effect-duplication case.
