## Frozen capability ablation

The held-out experiment uses four compositional arms:

```text
A = CORE_SYNC
B = A + BB-078 detached-operation capability
C = B + BB-079 append-only/cache-stable async-result context
D = C + BB-080 steering / wakeup / recovery
```

A is the control. B and C are diagnostic attribution arms only. D is the sole promotion candidate.

Worker bootstrap must resolve exact DONE BB-077/078/079/080 artifacts and exports. If B/C/D cannot be composed independently from delivered seams, BB-081 stops with `PLAN_INPUT_CONTRADICTION`; it must not approximate an ablation by editing delivered source.

All arms retain the exact BB-077 Harbor adapter, model/provider profile, task instruction, starting environment, capability surface, per-attempt budget, measurement contract, artifact extraction and verifier. Capability composition is the intended varying factor.

## Repeat and ordering protocol

Run two independent repeats per task and arm:

```text
4 tasks × 2 repeats × 4 arms = 32 registered arm attempts
```

The registered evaluation unit is:

```text
exact task digest + repeat index + frozen benchmark profile hash
```

This intentionally fits inside BB-077's existing external limits: USD 0.60 maximum per attempt and USD 25 maximum live cohort. At the per-attempt ceiling, 32 arm attempts cap at USD 19.20 before any provider-side savings.

The balanced execution schedule is:

```text
git-leak   r1 A B D C    r2 C D B A
pypi       r1 B C A D    r2 D A C B
kv-store   r1 C D B A    r2 A B D C
sanitize   r1 D A C B    r2 B C A D
```

Across the eight task-repeat blocks, every arm occupies each ordinal position exactly twice.

Every arm/task/repeat gets a fresh Harbor trial/environment, ExHarness runtime/coordinator state and provider `session_id`. Retries are appended attempts inside the same registered unit; they never replace it.

Repeated rollout evidence is used to expose variance, not to select the better rollout. Report each task as 0/2, 1/2 or 2/2 accepted plus failure-fingerprint recurrence.

## Attribution and primary decision

The report contains four matched vectors:

```text
A -> B   detached-operation contribution
B -> C   async-result/context contribution
C -> D   steering/wakeup/recovery contribution
D / A    primary candidate-vs-control decision
```

Report quality, normalized provider cost, input/output/cache accounting, model turns, tool calls, model/tool timing, useful overlap, prompt-prefix/cache observations, repeat consistency and failure fingerprints.

Do not collapse these into one harness score.

B and C cannot be promoted, even if their marginal metrics look better. They exist to explain where D's behavior comes from.

## Deterministic fault matrix

External held-out tasks measure quality/economics. Safety/recovery faults are a separate deterministic fixture suite so fault semantics do not depend on live-provider randomness or consume additional API budget.

Predeclared scenarios:

```text
PROVIDER_TIMEOUT             A B C D
PROVIDER_429                 A B C D
AMBIGUOUS_COMPLETION         A B C D
TOOL_FAILURE                 A B C D

KILL_AFTER_DURABLE_OPERATION   B C D
CANCEL_AFTER_DISPATCH          B C D
NON_RECONCILABLE_AMBIGUITY     B C D

DUPLICATE_TRANSITION             C D

DUPLICATE_WAKE                     D
STALE_MODEL_AFTER_STEER            D
```

Cells outside the declared applicability are `N/A`, not successful tests.

For D, promotion safety is absolute:

- duplicate external effects = 0;
- no lost terminal result;
- cancellation cannot relabel an unresolved external effect as cancelled;
- a stale/fenced model response dispatches zero actions/tools;
- duplicate completion ingress creates at most one active wake;
- NON_RECONCILABLE ambiguity escalates/fails closed;
- restart preserves exact operation/effect/generation identity.

A conclusive D safety violation yields `KEEP_SYNC_BASELINE`.

## Frozen promotion gate

The primary comparison is D vs A over eight matched task-repeat units.

Reuse the BB-077 gate unchanged:

```text
quality:
  accepted-task rate D >= A

safety:
  duplicate external effects = 0
  all required D recovery/cancel/stale-model/lost-result negatives pass

economics:
  median normalized provider cost ratio D/A <= 0.85

context:
  median prompt input token ratio D/A <= 0.90

interaction:
  median model turn ratio D/A <= 1.00

latency:
  median elapsed ratio D/A <= 1.10
```

All gates are conjunctive.

The reducer has exactly three outcomes:

```text
PROMOTE_ASYNC
KEEP_SYNC_BASELINE
INCONCLUSIVE
```

`PROMOTE_ASYNC` requires a complete 32-arm live cohort, complete required deterministic D fault evidence and every primary gate.

`KEEP_SYNC_BASELINE` requires complete/known evidence with any conclusive primary failure.

`INCONCLUSIVE` covers missing arm/repeat, live cohort budget stop, unknown primary token/cost accounting, verifier/task/profile/dependency drift, incomplete required fault evidence or invalid bindings. It publishes no async support claim.
