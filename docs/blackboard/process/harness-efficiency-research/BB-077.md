## Selected methodology

Treat the experimental unit as:

```text
fixed model snapshot
x fixed task + starting environment
x fixed task instruction/prompt
x fixed tool/capability surface
x fixed resource ceilings
x fixed artifact extraction + verifier
x HARNESS ARM
```

The harness arm is the intended varying factor. Native harness behavior is observed rather than normalized away.

Primary evidence:

- Harness-Bench (arXiv:2605.27922): shared sandboxed tasks, budgets and evaluators with artifact/trace/usage/validator evidence.
- Claw-SWE-Bench (arXiv:2606.12344): fixed prompt/runtime/workspace/patch/evaluator harness comparisons.
- The Scaffold Effect in Coding Agents (arXiv:2607.22585): fixed-model evidence that token efficiency and failure fingerprints can differ materially across scaffolds even when pass-rate deltas are smaller.
- Harbor v0.23.0, commit `1e5c5c6db929a10a140d05e606882c671ae20729`: selected neutral execution/evaluation substrate.
- Terminal-Bench 2.1 source commit `7131e4375048a0e408a8fb404b5f499d726b695b`: selected external workload snapshot.

At the 2026-09-27 check Harbor had 5,629 GitHub stars (Apache-2.0), mini-SWE-agent 7,998 (MIT), and OpenHands software-agent-sdk 1,174 (MIT). All reusable public implementation examples satisfy the standing >=1,000-star rule. Terminal-Bench 2.1 itself is workload data, not a reusable implementation example; its repository is below that threshold and is explicitly not used as implementation evidence.

## Neutral substrate decision

Use Harbor as an **outer benchmark runner**, never as ExHarness product runtime.

```text
Harbor trial
  |
  +-- same task environment
  +-- same instruction
  +-- same verifier
  +-- same model profile
  |
  v
ExHarnessHarborAgent   <-- one adapter class for every arm
  |
  +-- arm = DIRECT_CODEACT
  |      same JavaScript CodeAct strategy
  |      same reference JS executor
  |      same model adapter
  |      same capabilities
  |      minimal benchmark runtime shim
  |
  +-- arm = CORE_SYNC
         same JavaScript CodeAct strategy
         same reference JS executor
         same model adapter
         same capabilities
         current createAgentRuntime
```

The adapter may upload/install the declared benchmark runtime into the Harbor task environment and invoke the Node entrypoint. It must forward Harbor's task instruction verbatim and write a normalized run record. It must not rewrite the prompt differently by arm, choose a different model/tool surface, or make a quality judgment.

Harbor owns sandbox lifecycle, task/trial identity and verifier execution. ExHarness owns its native orchestration behavior and trace. Independent quality remains the Harbor task verifier result.

## Measurement contract

The rejected JEV candidate exposed one missing detail: the benchmark must distinguish observed model work from tool wait and residual harness time, and must make cache-prefix evidence explicit.

For every model request, the benchmark records a monotonic MODEL interval plus:

```text
stablePrefixSha256
stablePrefixBytes
dynamicSuffixSha256
dynamicSuffixBytes
provider prompt/completion tokens when known
provider cached/cache-write tokens when known
provider request identity
usage status
```

The stable prefix is the canonical fixed system/protocol/task/capability/static-context prelude. Turn number, observations, evolving history/prompt context and last validation error are the dynamic suffix.

Capability calls carry their own monotonic intervals. The report derives measured model-active time, union capability-active/wait time, model/capability overlap and `unattributedHarnessMs`. The residual is descriptive only: it must not be renamed “polling overhead” unless an explicit trace event proves that cause.

Cache status is intentionally conservative:

```text
CONFIRMED  provider cached_tokens > 0
MISS       provider cached_tokens = 0 with known usage
ELIGIBLE   stable prefix repeats but provider cache usage is unavailable
UNKNOWN    required prompt/provider evidence is unavailable
```

A repeated prefix hash proves stability/eligibility, not a provider cache hit.

## Predeclared future promotion gate

BB-077 only establishes the baseline, but BB-081's gate is frozen now, before async results:

```text
quality:
  accepted-task rate candidate >= CORE_SYNC

safety:
  duplicate external effects = 0
  required recovery negatives pass

economics:
  median normalized provider cost ratio <= 0.85

context:
  median prompt input token ratio <= 0.90

interaction:
  median model turn ratio <= 1.00

latency:
  median elapsed ratio <= 1.10
```

Any missing registered pair, unknown primary cost/token accounting, task/verifier drift, safety failure or quality regression yields `INCONCLUSIVE` or `KEEP_SYNC`, never `PROMOTE_ASYNC`.

The report keeps the complete vector and all attempts. It does not publish one opaque harness score or use best-of-k selection.
