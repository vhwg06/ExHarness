# BB-077 — Measure ExHarness harness tax and pin async-first baseline

Status: RESEARCH INPUT; no implementation authority.

## Outcome

ExHarness has a reproducible same-model, same-task harness-efficiency baseline that isolates orchestration overhead before any async runtime change is promoted.

## Current gap

Current Core measures capability calls and model usage but does not isolate harness-induced model turns, input/cache churn, tool-wait turns, polling/heartbeat overhead, operation overlap, or cost per accepted task. Unreal Agent and recent harness studies indicate this overhead can be material, but vendor benchmark claims are not ExHarness evidence.

## Research questions

1. Define the exact tool-heavy ExHarness fixtures and reset procedure for matched baseline runs.
2. Pin provider/model pricing and cache-usage fields for at least one real model route.
3. Define a non-inferiority quality bound and a cost/token improvement gate before candidate results exist.

## Required evidence discipline

Inspect the current Core source first. Compare the smallest existing-Core design with Unreal Agent v0.2.0 and at least one eligible >=1,000-star public implementation where a second implementation reference is useful. External benchmark claims remain attributed evidence until reproduced on the pinned ExHarness protocol.

The discriminating experiment must hold model/version, source/task fixture, tool surface, resource ceiling and acceptance semantics fixed. Record failures/retries and unknown usage. Include a negative recovery/effect-duplication case.

## Handoff

Resolve every research gap in the draft plan, narrow exact source/write scope and verification commands, then obtain a fresh Jev readiness judgment. Worker execution must preserve EffectOperation authority and current Core recovery invariants.
