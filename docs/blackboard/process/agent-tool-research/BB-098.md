# BB-098 — Observe supervised and direct agent-tool runs

Status: RESEARCH INPUT; no implementation authority.

## Outcome

Every agent-tool invocation, whether direct or ExHarness-supervised, produces one normalized, append-only, secret-redacted run trace. The trace combines:

- tool-native output;
- ExHarness events and spans;
- timing;
- repository diff statistics;
- verification outcomes;
- reported token usage.

Unreported values stay null with a reason; they are never estimated. A deterministic report aggregates traces per tool and arm.

## Current gap

- **DELIVERED_TRUTH.** Core exposes `eventSinks` (`write(event)`) and `createTraceRecorder({ sinks })`, which records MODEL, CAPABILITY, ACTION, STRATEGY and AGENT_RUN spans. Nothing persists them, joins them with external tool output, or compares runs.
- **Executed BB-097 probe.**
  - Only Codex exposes a structured event stream (`codex exec --json`).
  - agy exposes `--log-file`.
  - Kiro 2.24 non-interactive output is plain text.
  - Token usage is therefore not uniformly available.
- **PLANNED_CONTRACT.** The BB-065 `@exharness/benchmark` package owns attempts, evidence manifests and accounting. BB-098 must not duplicate them; it produces evidence that BB-099 attaches.

## Research questions

1. What is the minimal trace schema that serves both a direct run and a supervised run?
2. Which metrics are truthfully observable per tool, and how is "not reported" represented?
3. How are secrets kept out of stored traces?
4. How do traces stay evidence and never become acceptance?

## Approaches and evidence

- **Selected: JSONL trace plus per-tool output parsers.**
  - The Codex JSONL parser reads usage only from events that carry it.
  - The agy log file and Kiro stdout are stored as digests plus bounded excerpts.
  - Core events and spans are written through their existing sinks.
- **Rejected:**
  - An OTel or Langfuse exporter as the source of truth. It is an external dependency and not needed for a deterministic report; it can be added later as another sink.
  - Estimating tokens from text length. That fabricates evidence.
- **Redaction:** environment-derived secret values and common key patterns are removed before anything is written. A test asserts that a planted secret never appears on disk.

## Discriminating experiment

A fake Codex JSONL stream, a fake agy log and fake Kiro stdout are driven through BB-097's fake-CLI fixtures. The results must be:

- exact token fields for Codex;
- null tokens with a reason for Kiro and agy;
- identical traces from identical inputs;
- rejection of an edited trace that no longer matches its digest.

## Research revision r1 (after BB-097 delivery)

BB-097 is now DELIVERED, so its package is **DELIVERED_TRUTH** rather than a planned contract. The executed probe `docs/blackboard/evidence/BB-098/observation-probe.mjs` (result: `observation-probe-result.json`) drives the delivered package with the BB-097 fake CLI. ### Findings

- **Direct invocation.** `runAgentInvocation` returns `status`, `exitCode`, `signal`, `timedOut`, `durationMs`, `stdout`, `stderr`, `stdoutSha256`, `stderrSha256` and `truncated` for all three argv styles.
  - The digests cover the full streams; the text is bounded to `maxOutputBytes`.
  - There are no start/end timestamps, so a trace must take wall-clock timestamps around the call.
  - A direct run leaves its edits uncommitted in the working tree. Diff statistics therefore have to include untracked files.
- **Supervised invocation.** `runSupervisedTask` returns per-attempt summaries only (`exitCode`, `durationMs`, `timedOut`, `candidateSha`, `verification`, …). It does not return raw stdout/stderr. It also removes the agent log directory (the agy `--log-file`) and the worktree before returning.
  - A trace built from its return value alone therefore cannot contain output excerpts, log digests or diff statistics.
  - The draft's rule "no change to the BB-097 supervisor beyond eventSinks/tracer" cannot meet the objective for supervised runs.
- **Core observability through the supervisor.** `eventSinks` receive `HARNESS_*`, `AGENT_RUN_*` and `CAPABILITY_INVOKED/STARTED/COMPLETED` events. `tracer` sinks receive `CAPABILITY` spans (`avo.act`, `verify.<name>`, `avo.evaluate`, `avo.promote`) plus run-level `STRATEGY` and `AGENT_RUN` spans.
  - Each attempt opens with a `CAPABILITY_INVOKED` event whose `payload.name` is `avo.act`, so events and spans can be assigned to attempt windows deterministically.
  - Event payloads can carry candidate ids and session ids, so a trace stores only event types and capability names.
- **Upstream Codex usage schema.** `codex exec --json` emits `turn.completed` with a `usage` object. The fields are `input_tokens`, `cached_input_tokens`, `output_tokens`, `reasoning_output_tokens` and, in newer versions, `cache_write_input_tokens`; `turn.failed` and `error` events carry no usage. This comes from the upstream `codex-rs/exec/src/exec_events.rs` and SDK `events.ts` and was not executed here. The BB-097 fake codex stream emits no usage event.
- **Kiro structured output.** Kiro documents `--output-format stream-json` for `--no-interactive` (engine v2/v3 only), and `--output-format` appears in the probed 2.24.1 help. Its event schema and any usage fields are undocumented, and the delivered BB-097 adapter does not request it (adapter changes are out of scope). Kiro traces therefore stay text-only with usage null.
- **agy.** `--log-file` exists and has no documented format, and there is no structured stdout. Usage stays null.

### Decision changes

- The BB-097 supervisor gains exactly one additive, default-null option, `invocationObserver`. It is awaited inside the ACT step after the candidate commit and before any cleanup, and receives:
  - `attemptIndex`, `request`, `timeoutMs`;
  - the raw invocation result and wall-clock `startedAt`/`endedAt`;
  - `logFile`, `worktree`, `candidateBefore`, `candidateAfter`, `outcome` and `foldedAgentCommits`.

  With the option null, behavior is byte-identical, and all existing BB-097 tests stay unchanged.
- Supervised traces are written after the run returns. Each one joins the observer facts, the attempt's verification records and the attempt's Core event/span window.
- Redaction runs on the full captured text before excerpting. Codex token fields are summed only over `turn.completed.usage`.
