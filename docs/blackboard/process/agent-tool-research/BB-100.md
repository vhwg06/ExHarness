# BB-100 — Opt-in supervised agent-tools Backend adapter

Status: RESEARCH INPUT; no implementation authority.

## Outcome

Production Backend work can execute through the delivered supervised agent-tools loop as an opt-in adapter, producing the unchanged BackendWorkResult schema with verifier-grounded acceptance, while the default CodeAct BackendWorker path stays byte-identical.

## Current gap

- **DELIVERED_TRUTH.** `createBackendWorker({ strategy, workspace, verifiers })` runs Core `createHarness` whose `objective.evaluate` PASSes when `candidate.version !== order.revision`. `runSupervisedTask` is a closed loop over Core with verifier-PASS acceptance. No `packages/agentic-system` module imports agent-tools.
- **PLANNED_CONTRACT.** BB-066 is OpenHands under `DomainExecutionController`. BB-089 is Oracle context adoption. Neither composes Codex/Kiro/agy as Backend work.
- **Executed probe** `docs/blackboard/evidence/BB-100/productization-probe-result.json`.

## Research questions

1. Should composition inject `createSupervisedAgentStrategy` into `createBackendWorker`, or map `BackendWorkOrder` to `AGENT_TASK_V1` and call `runSupervisedTask`?
2. Which evaluate rule is acceptance on this path: mutation-only (BackendWorker) or verifier PASS (agent-tools)?
3. How is `BackendWorkResult` projected without claiming APPLIED on EXHAUSTED/TOOL_UNAVAILABLE/NO_CHANGE?
4. What stays unchanged on the default CodeAct path?

## Approaches and evidence

- **Selected: mapping adapter.** Probe shows different ACT kinds (`workspace.act` vs `RUN_AGENT_TOOL`) and different evaluate rules. Injecting the supervised strategy into BackendWorker would silently weaken or replace mutation-only evaluate.
- **Rejected:** replacing BackendWorker evaluate globally; wrapping the CLI as `model.generate()`.
- **Deferred:** wiring `runBackendThenQaObjective` / durable Backend→QA (BB-104); DomainExecutionController OpenHands (BB-066).

## Discriminating experiment

Deterministic fake CLI inside a temporary git repository. The adapter must:

- ACCEPT/APPLIED only after declared Backend verifiers PASS at the candidate commit;
- refuse APPLIED on FIX_AFTER_FEEDBACK until the retry PASSes, and never APPLIED on NEVER_FIX, AUTH_FAIL, CLAIM_SUCCESS_NO_EDIT;
- leave `createBackendWorker` without an agent-tools import;
- preserve the source repository HEAD.
