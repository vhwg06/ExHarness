# BB-103 — ExHarness verification as stdio MCP tools

Status: RESEARCH INPUT; no implementation authority.

## Outcome

ExHarness exposes verification and run-status as MCP tools over stdio so a supervised CLI agent can query independent verification during its own loop. Promotion remains ExHarness-owned and is never an MCP tool.

## Current gap

- **DELIVERED_TRUTH.** Outer supervision is the only verification path. agent-tools has no MCP symbols. Codex and Kiro expose `mcp add/list` (BB-097 CLI probe).
- **BB-097 constraint.** In-tool MCP/hooks were deferred until BB-099 measures supervision value. This task designs an opt-in query surface; it does not replace outer supervision or wait for a value verdict.
- **Oracle living.** MCP is a source/capability adapter, not product authority.

## Research questions

1. Which MCP tools exist, and which are forbidden (promote/accept/merge)?
2. Official `@modelcontextprotocol/server` (13.5k stars, MIT) versus a zero-dependency JSON-RPC stdio implementation (agent-tools currently has no runtime npm dependencies)?
3. How is the server scoped to one worktree without writing user CLI config?
4. How does outer supervision remain the only promotion authority?

## Approaches and evidence

- **Selected: zero-dependency stdio JSON-RPC** implementing tools `exharness_verify` and `exharness_status` only. Keeps the no-runtime-dep contract. Discriminating tests speak the MCP initialize/tools/call messages.
- **Rejected as default:** adding `@modelcontextprotocol/server` as a runtime dependency in this task. Research may record it as a later optional adapter once a pin and license/size check exist.
- **Rejected:** MCP `promote` tool; writing `~/.codex/hooks.json` or Kiro/agy user config.

## Discriminating experiment

A fake MCP client on stdio calls `exharness_verify` against a worktree whose test fails, then after a fix, PASSes. `tools/list` must not contain promote/accept/merge. A supervised run without the MCP option never listens. A planted `exharness_promote` registration is rejected at server construction.

### Findings

- No MCP export/option/adapter/CLI token. `runSupervisedTask` options: `tool, task, model, maxAttempts, timeoutMs, maxFeedbackChars, permissionProfile, env, eventSinks, tracer, invocationObserver`. Strategy options: `task, maxAttempts, maxFeedbackChars`. Zero runtime deps.
- `createLocalCommandVerifier` returns `{ name, verify }`; `verify({ candidate })` returns `{ claim, status, evidence, summary }`; reason is evidence `:reason=` (`PASS`/`FAIL`/`REVISION_MISMATCH`, …).
- `CLAIM_SUCCESS_NO_EDIT` is `EXHAUSTED`. NDJSON `initialize` over PassThrough round-trips `2025-03-26`. Codex/Kiro `mcp add` writes user config; frozen argv has no MCP flag. SDK v2 speaks 2026-07-28 `server/discover`; Codex 0.158 speaks 2025-era `initialize`/`tools/list`/`tools/call`.
