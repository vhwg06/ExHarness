## Outcome

Grok Build (`grok`, model pin `grok-4.6`) is a first-class tool id in `@exharness/agent-tools`, usable on both the direct observation arm and the ExHarness-supervised arm, with real JSON usage/cost when the CLI reports it. Codex, Kiro and agy stay on their delivered contracts; on a host without those binaries they remain `TOOL_UNAVAILABLE` / `NOT_INSTALLED` / `NOT_EVALUATED`.

## Current gap

- **DELIVERED_TRUTH.** `AGENT_TOOLS = { codex, kiro, agy }`. `parseToolOutput` dispatches those three ids. `exharness-agent` USAGE is `--tool <codex|kiro|agy>`. Observation reports Codex usage from `turn.completed` and null-with-reason for Kiro/agy.
- **Executed probe.** Grok Build 1.0.44 (`5b807183dd79`) exists at `~/.grok/bin/grok` and is authenticated (`grok models` lists `grok-4.6`). It is **not** on the default `PATH`, so `resolveExecutable("grok")` returns null unless the operator extends PATH or passes `--command`.
- **Live headless (two runs, no third).**
  1. `--output-format json -m grok-4.6 --cwd <temp git repo> --always-approve --disable-web-search --no-subagents --no-auto-update --prompt-file <file>`: exit 0 in 5917 ms, created `hello.txt` with `hi`, JSON keys `modelUsage, num_turns, requestId, sessionId, stopReason, text, total_cost_usd, total_cost_usd_ticks, usage`. `usage` keys include `input_tokens, cache_read_input_tokens, cache_creation_input_tokens, output_tokens, reasoning_tokens, total_tokens`. Observed: `cache_read_input_tokens=42752`, `output_tokens=239`, `reasoning_tokens=117`, `num_turns=3`, `total_cost_usd=0.01200404`, `stopReason=end_turn`, `sessionId` UUID. The integer `usage.input_tokens` was present as a key; a first-pass substring redaction of `TOKEN` dropped the value. The parser still reads the field when it is an integer.
  2. Same flags with a **positional** prompt and stdin ignored: exit 1 in 50 ms, stderr `Error: No such device or address (os error 6)`, no JSON, no edit. Headless spawn must use `--prompt-file`, not a positional prompt.
- **Missing binary.** `spawn` of a non-existent command is `ENOENT` (`errorCode: ENOENT`, `exitCode: null`), which the delivered process runner already maps to `TOOL_UNAVAILABLE`.
- **Hidden flag.** `--no-auto-update` is accepted (`--version` still succeeds) and is not in `--help`. Unknown flags are rejected.
- **PLANNED_CONTRACT.** None for this adapter. BB-099 measures Codex/Kiro/agy; adding grok there is out of scope.

## Research questions

1. Which grok headless surface is spawn-safe without a TTY?
2. Where do usage and cost live in `--output-format json`?
3. How do permission profiles map onto grok flags without reading `~/.grok`?
4. How is a prompt kept out of traces when it is passed by `--prompt-file` rather than as an argv word equal to the prompt?

## Approaches and evidence

- **Selected: `grok` argv + `--output-format json` + `--prompt-file` outside the worktree.** Live run 1 edited `--cwd` and returned usage/cost/sessionId. `--prompt-file` is labeled single-turn in help but ran a 3-turn agent that wrote `hello.txt`.
- **Rejected: positional prompt.** Live run 2 failed immediately with ENXIO when stdin was not a TTY (the process runner uses `stdio: ignore` when `stdin` is null).
- **Rejected: `grok agent headless`.** That subcommand is a WebSocket relay, not a local spawn.
- **Rejected: estimating `input_tokens` after the first-pass redaction loss.** Unreported or unretained numbers stay null with a reason.
- **Reuse:** `defineAgentTool`, `runAgentInvocation`, `runObservedInvocation`, `runSupervisedTask`, `parseToolOutput` dispatch, `redactArgv`, fake-CLI tests. Pass `cwd` and `promptFile` through the existing request object (agy already requires `logFile`).

## Discriminating experiment

`packages/agent-tools/test/fixtures/fake-grok.mjs` impersonates grok argv (`--version`, `--output-format json`, `--prompt-file`, permission flags, `-m`/`--model`) and emits the probed JSON shape. Tests never spawn the real `grok` binary.

Probe findings used as closed decisions:

| Gap | Resolution |
|---|---|
| Headless spawn | `--output-format json` plus `--prompt-file` (file lives in supervisor `logDir` / a temp path, never in the worktree). Positional prompt is not used. |
| Model pin | Always pass `--model`; default `grok-4.6` when `request.model` is null. |
| cwd | Pass `--cwd` with the spawn cwd (process-runner forwards `cwd` into `buildInvocation`). |
| Permissions | `WORKSPACE_EDIT` → `--permission-mode acceptEdits`; `FULL_AUTO` → `--always-approve`. Always `--disable-web-search --no-subagents --no-auto-update`. |
| Usage/cost | `usage.input_tokens`, `usage.cache_read_input_tokens`, `usage.output_tokens`, `usage.reasoning_tokens`, top-level `total_cost_usd`, `num_turns`, `sessionId`. Null + `GROK_USAGE_NOT_REPORTED` when integers are absent. Never estimate. Extra grok-only field `totalCostUsd` on the usage object; Codex/Kiro/agy usage objects stay six fields. |
| Resume | `--resume <sessionId>` when `resume.sessionRef` is a string; `--continue` when resume is non-null without a session id. `--session-id` is new-session only and is not used to resume. |
| Missing binary | Delivered `ENOENT` → `TOOL_UNAVAILABLE`. |
| PATH | Adapter command remains `grok`. Operators pass `--command ~/.grok/bin/grok` or put that directory on PATH. The adapter does not read `~/.grok`. |
| Prompt in traces | Prompt is not an argv word; `promptSha256` still binds it. `--prompt-file` path is outside the worktree and is disposed with scratch. |
