# BB-099 — Measure ExHarness-supervised versus direct agent-tool delivery

Status: RESEARCH INPUT; no implementation authority.

## Outcome

A pre-registered, fixed-factor experiment answers, per tool, whether ExHarness supervision delivers more hidden-test-accepted changes than the same tool used directly, and at what cost. The answer comes from independent evaluation. The tool's own claims, ExHarness's own verdict and Jev prose are not evidence of value.

## Research questions

1. Which arms isolate harness value? Candidates are DIRECT_SINGLE, DIRECT_RETRY and EXHARNESS_SUPERVISED.
2. Which task suite has independent acceptance that the agent cannot see or edit?
3. Which primary metric and decision rule are fixed before any live run?
4. How are cost, rate limits and non-determinism bounded and reported?

## Approaches and evidence

- **Arms.** Each tool gets three arms: DIRECT_SINGLE, DIRECT_RETRY (K invocations with a generic continue prompt) and EXHARNESS_SUPERVISED (K attempts with verification feedback). Tool version, model, permission profile, timeouts and K are fixed per tool.
- **Suite.** Owned local fixtures, each a small git repository with visible tests and hidden acceptance tests. Hidden tests are stored outside the worktree and applied only at independent evaluation.
- **Primary metric.** Hidden-acceptance rate per arm.
- **Secondary metrics.**
  - False-success rate: the tool exits successfully or the arm reports done while hidden tests fail.
  - Wall time.
  - Invocations.
  - Reported tokens (null when unreported).
- **Decision rule.** A paired bootstrap per tool over tasks × repeats.
  - SUPERVISED is superior when the 95% interval of (SUPERVISED − DIRECT_RETRY) excludes 0 on the positive side.
  - It is inferior when the interval excludes 0 on the negative side.
  - Otherwise the result is INCONCLUSIVE.
  - Every outcome is reported; none is required.
- **Rejected:** public benchmarks as the first suite (cost and contamination), a Jev-judged value verdict, and unmatched budgets.

## Discriminating experiment

Deterministic calibration uses BB-097 fake CLIs with scripted behaviors:

| Scripted behavior | Required reducer output |
|---|---|
| Fixes on the first try | Arms tie |
| Fixes only with feedback | SUPERVISED is superior |
| Never fixes | Arms tie at zero |
| Claims success on a failing tree | Counted as false success |

The reducer and audit must reproduce each of these. A live run is opt-in, cost-capped and needs the user's authenticated CLIs.
