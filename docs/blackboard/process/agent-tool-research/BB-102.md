## Discriminating experiment

A task with `requiredFiles: ["src/app.js"]` at a known revision must spawn only after a consumable EXACT resolution whose item digest matches the file at that revision. A missing path, a stale snapshot, or `maxMaterializedBytes: 1` must not spawn. A task without `requiredFiles` must never construct a catalog.

### Probe findings

- **Identifiers.** `@exharness/oracle` exports `createOracleContextResolver`, `createExactRepositoryProvider`, `createSourceCatalog`, `createRetrievalPlanner`, `assertConsumableContextResolution`, `defineContextRequirement`, `DurabilityFailure`. `AgentTaskStatus` is exactly `{ ACCEPTED, EXHAUSTED, TOOL_UNAVAILABLE }` — there is no `CONTEXT_UNSATISFIED` status. `runSupervisedTask` options are `tool, task, model, maxAttempts, timeoutMs, maxFeedbackChars, permissionProfile, env, eventSinks, tracer, invocationObserver`. Supervisor does not import Oracle. `validateAgentTask` currently returns frozen `{ id, repositoryRoot, baseRevision, prompt, verifications }` and silently drops `requiredFiles`.
- **EXACT facade.** One REQUIRED evidence per path with `source: { kind: "REPOSITORY", ref, snapshot: { mode: "EXACT", ref: revision }, itemRefs: [path] }`, catalog = `createExactRepositoryProvider` + an EXACT snapshot authority whose `observe()` returns the pinned revision, then `createRetrievalPlanner` + `createOracleContextResolver`. A git `show <revision>:<path>` reader yields `COMPLETE`, consumable items whose content matches the file at that revision and whose provenance includes `SOURCE_REF`.
- **Missing file.** Reader throw → resolution `status: "UNSATISFIED"`, `unresolved.reason: "SOURCE_FAILURE"`. `assertConsumableContextResolution` rejects it. Nothing is thrown by `resolve()`.
- **Budget.** Planner reserves `min(8192, remaining)` bytes per item. `maxMaterializedBytes: 8192` is `COMPLETE` for a small file. `maxMaterializedBytes: 2` is `UNSATISFIED` with `BUDGET_EXHAUSTED`. `maxMaterializedBytes: 1` throws `TypeError: consumed below materialization/step` because even an empty item list materializes as 2 bytes. Fail-closed must catch both the UNSATISFIED result **and** that TypeError. The draft's `maxMaterializedBytes: 1` example is the thrown path, not a clean UNSATISFIED.
- **Stale.** EXACT mode does not compare repository HEAD to `baseRevision`. Stale is the facade pre/post fence: a snapshot authority whose second `observe()` returns a different `snapshotRef` throws `DurabilityFailure` with `reason: "STALE_DURING_RESOLUTION"` (`source drift during resolution: file-0`) before any consumer receives items.
- **Worktree projection.** Writing `.exharness/context/src/app.js` into a `createLocalGitWorkspace` worktree dirties porcelain (`?? .exharness/context/src/app.js`). Appending `.exharness/` to `git rev-parse --git-path info/exclude` (absolute on this git) clears porcelain and leaves HEAD at `baseRevision`. Without the exclude, `git add -A` after a NO_CHANGE agent would commit the grounded copies and break candidate identity. `assertSafeWorkspacePath` (already exported from `@exharness/agentic-system`) accepts `src/app.js` and rejects `..`, absolute paths, and `.git` segments with `LOCAL_WORKSPACE_UNSAFE_PATH`.
- **Fail-closed vs status.** Backend/QA uses thrown `OracleContextBlockedError` in agentic-system; that class is not an agent-tools export. Widening `AgentTaskStatus` with `CONTEXT_UNSATISFIED` would make the CLI (`ACCEPTED → 0`, `EXHAUSTED → 1`, else `2`) and every existing status consumer treat context failure as `TOOL_UNAVAILABLE`. A thrown typed error does not widen the enum and matches "blocks before any agent process starts".

### Draft researchGap resolution

Draft gap: *Pin CONTEXT_UNSATISFIED as a new AgentTaskStatus versus a thrown typed error so existing AgentTaskStatus consumers do not silently treat it as EXHAUSTED.*

**Resolved: thrown typed error, enum unchanged.** Implementation creates `AgentTaskContextError` (`name: "AgentTaskContextError"`, `code: "CONTEXT_UNSATISFIED"`) in `packages/agent-tools/src/task-context.js`. `error.status` carries the Oracle resolution status (`UNSATISFIED` / `PARTIAL`) or `"STALE"` for `DurabilityFailure`. `AgentTaskStatus` stays `{ ACCEPTED, EXHAUSTED, TOOL_UNAVAILABLE }`. `runSupervisedTask` does not return a supervised result on context failure; it throws before `createLocalGitWorkspace` and before spawn. Tasks without `requiredFiles` never construct a catalog and never throw this error. The CLI is not in write scope: invalid tasks already throw `TypeError` from `validateAgentTask`, and this follows that seam.
