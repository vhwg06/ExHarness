# BB-102 — Oracle-grounded declared context for agent-tool tasks

Status: RESEARCH INPUT; no implementation authority.

## Outcome

An AGENT_TASK can declare required files that Oracle resolves through `createOracleContextResolver` as EXACT snapshot-bound context. The agent receives those bytes as grounded input and cannot treat unresolved or stale context as current.

## Current gap

- **DELIVERED_TRUTH.** `validateAgentTask` accepts `{id, repositoryRoot, baseRevision, prompt, verifications}` only. Oracle facade `createOracleContextResolver` is delivered.
- **PLANNED_CONTRACT.** BB-089 adopts the facade for Backend/QA production context. Agent-tools is a different consumer.
- **Executed probe:** `hasRequiredFilesField: false`, `hasContextRequirement: false`.

## Research questions

1. Optional `requiredFiles` on AGENT_TASK_V1: how is it mapped to an EXACT ContextRequirement at `baseRevision`?
2. Prompt prefix versus a worktree `.exharness/context/` directory for grounded bytes?
3. When does resolution run relative to spawn, and what blocks the agent?
4. How do callers without `requiredFiles` stay byte-identical?

## Approaches and evidence

- **Selected: optional requiredFiles + EXACT facade.** Same mapping style as BB-089, but owned by agent-tools and targeting AGENT_TASK, not BackendContextSchema.
- **Selected projection:** grounded prompt prefix plus read-only `.exharness/context/<path>` files inside the worktree (not the source repository).
- **Rejected:** lexical/semantic/graph retrieval for this task; CURRENT-mode heads; making requiredFiles mandatory.

## Discriminating experiment

A task with `requiredFiles: ["src/app.js"]` at a known revision must spawn only after a consumable EXACT resolution whose item digest matches the file at that revision. A missing path, a stale snapshot, or `maxMaterializedBytes: 1` must not spawn. A task without `requiredFiles` must never construct a catalog.
